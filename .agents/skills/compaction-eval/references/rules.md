# 压缩质量评估规则

## 背景

- 一个编码 Agent 会话中，完整消息区间 [{lo}..{hi}] 在{phase}阶段被压缩为摘要。
- 会话首条用户任务：{task}
- `source.xml` 是压缩输入的原文视图，即 getHistory 结果。观察阶段的输入是区间内完整消息；反思阶段的输入是已有 `<history>` 块的合并视图，其中可能已含更早压缩产生的摘要条目。
- `after.md` 是区间之后的真实后续轨迹，用来判断哪些信息后来真的被用到或需要。
- 压缩后主模型只能看到摘要和未压缩尾部。recall 工具可按 index 召回原文，但只有意识到缺信息时才会召回。
- 用户消息与 skill 原文由插件逐字保留，不在评估范围内。

## 压缩器收到的要求

- 将关联的 assistant 消息按逻辑划分为连续模块，区间压缩。
- 描述行为逻辑，强调关键的结论、产出和任务；涉及的文件保留完整路径。
- 摘要粒度按后续用途分配，与消息位置无关：未完成的任务、当前状态、待办与未解决的问题保留细节；已完成的子任务只保留结果、决策及理由、排除的方案及原因。
- 不可再生的信息不论早晚都要保留：用户约束与偏好、决策、报错原文、外部返回的关键数据、验证过的结论。
- 可以低成本重新获取的内容只记来源与要点。
- 反思阶段额外要求：重新压缩已有摘要条目时保留其中的不可再生信息，不要逐轮缩减。

## 信息分类

- A 不可再生且任务相关，权重 3：日志之外无法再获得、或缺失后模型难以察觉的信息。例：已执行的动作与进度、死路与排除结论、决策及理由、时点性观测、当前状态、任务规划。
- B 可再生但代价高，权重 2：可通过重新执行工具恢复，但需要大量步骤或时间。
- C 廉价可再生，权重 1：一两次工具调用即可重新获得的任务相关信息。
- D 无关信息，权重 0：已失效的瞬时信息、与任务无关的业务数据、冗余过程细节。省略最佳，一句话概括次之，详细保留最差。
- 凭据如 token、密钥出现在摘要中即扣分。

## 位置

位置只用于分段诊断，不影响得分。

- head：index {head}
- mid：index {mid}
- tail：index {tail}

## 判定

- 保留：信息要点完整、准确。
- 部分：提到了但缺少关键要素，如缺路径参数、缺原因。
- 丢失：摘要中找不到。
- 歪曲：摘要内容与原文矛盾或张冠李戴。
