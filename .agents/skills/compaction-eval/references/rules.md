# 压缩质量评估规则

## 背景

- 一个编码 Agent 会话中，完整消息区间 [{lo}..{hi}] 在{phase}阶段被压缩为摘要。
- 会话首条用户任务：{task}
- 压缩后主模型只能看到摘要和未压缩尾部。recall 工具可按 index 召回原文，但只在意识到缺信息时才会召回。
- 用户消息与 skill 原文由插件逐字保留，不评。

## 文件

- `source.xml`：压缩输入视图，即 getHistory 结果。
  - 观察阶段：区间内完整消息。
  - 反思阶段：已有 `<history>` 块的合并视图，可能含更早压缩产生的摘要条目。
- `after.md`：区间之后的真实轨迹，用于判断哪些信息后来被用到或需要。

## 压缩器收到的要求

- 将关联的 assistant 消息按逻辑划分为连续模块，按区间压缩。
- 描述行为逻辑，突出关键结论、产出和任务；涉及的文件保留完整路径。
- 粒度按后续用途分配，与消息位置无关：
  - 未完成的任务、当前状态、待办与未解决的问题：保留细节。
  - 已完成的子任务：只保留结果、决策及理由、排除的方案及原因。
- 不可再生信息不论早晚都保留：用户约束与偏好、决策、报错原文、外部返回的关键数据、验证过的结论。
- 可低成本重新获取的内容只记来源与要点。
- 反思阶段：重压缩已有摘要条目时，保留其中的不可再生信息，不逐轮缩减。

## 信息分类

- A，不可再生且任务相关：日志之外无法再获得，或缺失后模型难以察觉。例：已执行的动作与进度、死路与排除结论、决策及理由、时点性观测、当前状态、任务规划。
- B，可再生但代价高：重新执行工具可恢复，但需要大量步骤或时间。
- C，廉价可再生：一两次工具调用即可重新获得的任务相关信息。
- D，无关：已失效的瞬时信息、与任务无关的业务数据、冗余过程细节、凭据。

## 位置

只用于分段诊断，不影响得分。

- head：index {head}
- mid：index {mid}
- tail：index {tail}

## 判定

A/B/C 类：

- 保留：要点完整、准确。
- 部分：提到了，但缺少关键要素，如路径、参数或原因。
- 丢失：摘要中找不到。
- 歪曲：与原文矛盾或张冠李戴。

D 类：

- 已省略：摘要中没有。
- 已概括：一句话带过。凭据仅提及而不含值也算。
- 详细保留：保留了细节或凭据值。
